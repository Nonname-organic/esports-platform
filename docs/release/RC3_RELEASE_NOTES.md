- 作成: 2026-11-10（RC2 確定後工程：公開前修正）
- 対象: ブランチ `release/rc3`。RC2（`d3865c4`）に、公開前に直す S7・S8・S9 を加えた版

- **本書は本番公開の承認ではない。** RC3 候補の確定と本番公開は別の判断になる
- RC2 の内容（[RC2_RELEASE_NOTES.md](RC2_RELEASE_NOTES.md)）はすべて含む。RC2 のリリースノートの「公開時の制限事項」は、本書の同じ節で置き換える
- 変更の詳細は [RC3_CHANGES.md](RC3_CHANGES.md)

## 本番への反映について（先に読む）

- Deploy workflow は無効のまま。デプロイ・切り戻しの手順とチェックリストは RC2 の文書
  （[デプロイ手順](RC2_DEPLOYMENT_RUNBOOK.md)・[切り戻し手順](RC2_ROLLBACK_RUNBOOK.md)・[チェックリスト](RC2_PRODUCTION_CHECKLIST.md)）をそのまま使う
- RC3 で増えたマイグレーションはない（DB の版は 030 のまま）
- RC2 の手順との違いは次の 3 点

1. **デプロイの後、全利用者が一度ログインし直しになる。** RC3 は、パスワードの印を持たないトークン（RC2 以前に発行したもの）を受け付けない。
   画面は 401 を受けて更新に失敗し、ログイン画面へ戻る。デプロイ直後に 401 が増えるのは想定どおり。公開の前に利用者へ知らせる
2. 公開の集計は Redis のキャッシュに残る（実績カード・通算成績 10 分、ランキング・ランクカード・選手プロフィール 15 分、選手の分析 30 分、BAN/PICK 5 分）。
   デプロイ直後のこの間は、限定公開・非公開の大会を数えた古い値が出ることがある。待てば入れ替わる。すぐに消す場合の対象は
   `team:achievement:*`・`career:*`・`ranking:*`・`team_rank_card:*`・`player_rank_card:*`・`player_profile:*`・`player_analysis:*`・`analytics:veto:*`
   （本番の作業なので、デプロイの工程で承認を得てから）
3. RC2 以前のイメージへ切り戻しても、RC3 が発行したトークンはそのまま使える（以前のコードは印を見ない）。DB は変えていないので、切り戻し手順は RC2 と同じ。
   ただし切り戻すと、**RC3 でパスワードの変更によって失効させたトークンも、期限内なら再び通る**（リフレッシュは発行から 7 日。更新を続ければ延びる）。
   切り戻している間は、パスワードを変えても他の端末のセッションは失効しない。侵害の対応でパスワードを変えた利用者がいる時期に切り戻すなら、
   SECRET_KEY の入れ替え（全員がログインし直しになる）もあわせて判断する。RC3 へ戻すと、切り戻しの間に発行したトークンは通らなくなる（もう一度ログインし直し）

## RC2 から加わったもの

### 公開範囲（S7）

| 内容 | 以前 |
|---|---|
| チームの実績カード、公開ランキング（チーム・選手）、ランクカードの履歴、チーム・選手の通算成績（勝敗・連勝・対戦相手・マップ・エージェント・優勝数）、大会をまたぐ分析（勝率・マップ・エージェント・推移・選手ランキング・ヒートマップ・BAN/PICK、大会を指定しない選手のスタッツ）は、一覧に載る大会（公開で、下書きでないもの）だけを数える | 限定公開・非公開の大会の大会名・順位・対戦相手・成績が、誰でも見られる集計に出ていた |
| 大会の ID を指定した画面（大会の詳細・大会単位の分析）は、これまでどおり。限定公開は「URL を知っている人だけが見られる」仕様のまま | 同じ |

限定公開・非公開の大会に出たチーム・選手は、実績・RP・通算成績の数字が下がることがある（本来の値に戻る）。

### 選手の成績（S8）

| 内容 | 以前 |
|---|---|
| 成績（マップごとの保存・結果の登録・Bot の結果確定）は、その試合に出る 2 チームの所属選手のぶんだけ受け付ける。所属は、試合の期間と重なる所属行で見る（試合の開始の前に抜けていない、終わった試合なら終わる前に入っていた）。あとで抜けた選手の成績は直せる。同じ選手を 1 マップに 2 回入れることもできない。管理者も同じ。違反は 400 で、何も保存しない | 主催者は任意の選手 ID・チーム ID の成績を書けた。出場していない他人の、公開の通算成績を変えられた |
| **残る手口**: チームのオーナー・キャプテンは、本人の承諾なしに利用者を所属させられる（以前からの仕様）。主催者の機能は誰でも有効にできるので、大会と出場チームの両方を持つ利用者は、試合の前か試合中に他人を所属させて、その試合の成績を書ける。下の制限事項を参照 | 同じ |

### セッション（S9）

| 内容 | 以前 |
|---|---|
| パスワードの変更・再設定で、それより前に発行したトークン（本人の端末・他の端末・リフレッシュトークン）がすべて通らなくなる。トークンにパスワードのハッシュから作る印（HMAC）を入れ、認証と更新のたびに今のハッシュの印と比べる | 変更前のトークンが、アクセスは最長 15 分、リフレッシュは最長 7 日（更新を続ければ期限なく）使えた |
| 設定画面でパスワードを変えると、その端末もログアウトしてログイン画面へ移り、新しいパスワードでのログインを案内する | 変更後もその端末はそのまま使えた |

## マイグレーション

RC3 での追加・変更はない。028〜030 は RC2 と同じ（[RC2_RELEASE_NOTES.md](RC2_RELEASE_NOTES.md#マイグレーション)）。

## 公開時の制限事項

| 区分 | 内容 |
|---|---|
| **公開前に判断が要る（独立監査で HIGH）** | S8 の残り。チームへの所属は、オーナー・キャプテンが本人の承諾なしに作れる。大会と出場チームの両方を持つ利用者は、試合の前か試合中に他人を所属させ、その試合の成績を書いて、他人の公開の通算成績・分析・スカウトの値を変えられる。終わった試合への後付けは RC3 で塞いだが、試合の再開（主催者の操作）で試合中に戻せば、また書ける。所属させると、本人の活動に「加入しました」と出て、チームの監査記録にも残る。根本の対策は、所属の承諾制（招待して本人が承認）か、参加登録時の名簿の固定で、どちらも仕様の判断とマイグレーションが要る |
| 未対応（MEDIUM・以前から） | 同じく承諾なしの所属で、そのチームの全期間の RP・順位つきの大会履歴が、所属させた選手に付く（ランクカード・選手ランキング・大会履歴は所属の期間を見ていない）。対策は上と同じ |
| 未対応（MEDIUM） | 異議は誰にも通知されず、異議の記録（`match_disputes`）の一覧・解決の画面がない。主催者は試合ページで状態を見て裁定する（S11。今回は直さない） |
| 既存の動き | OCR の回数制限（利用者ごと・試合ごとに 1 分で 6 回）は、同じ利用者が同じ試合に送るほかのリクエスト（試合の詳細・報告の状態など）と回数を共有する。制限のキーが URL の先頭 50 文字で切られるため（最初の版からの動き）。試合ページを開いたまま続けて OCR を使うと 429 になることがあり、1 分待てば通る（今回は直さない） |
| 手順で回避（MEDIUM） | デプロイの途中、新しいコードが 027 のスキーマで動く間（最大 60 秒ほど）は、結果の登録・確認が 500 になる。先にマイグレーションを流す手順で避ける（S13、[デプロイ手順](RC2_DEPLOYMENT_RUNBOOK.md)） |
| 仕様（S9） | サーバー側のログアウトはない。画面のログアウトは、その端末のトークンを消すだけ。パスワードを変えずに「全端末からログアウト」する手段もない |
| 仕様（S9・LOW） | Discord Bot からの操作は、Discord の連携で本人を確かめる。パスワードを変えても連携は切れないので、盗まれたセッションで攻撃者の Discord を連携されていると、変更後も Bot 経由で本人として操作できる。初期公開では Bot を有効にしない。有効にする前に、パスワードの変更・再設定で連携を外すかを決める |
| LOW（S9） | パスワードの変更・再設定やメールの変更をしても、発行済みの再設定リンク（30 分有効）は消えない。レート制限の利用者の識別は署名だけを見るので、失効したアクセストークン（最長 15 分）でも、その利用者の回数の枠を使える（認証は通らない） |
| LOW（S7） | 次は公開範囲で絞っていない。どれも大会名・大会 ID は返さない。① 集計表から返す `/analytics/maps/stats`・`/analytics/compositions`（書き手は SQS の処理で、本番で SQS が未設定なら表は空）② チームの rating（`rankings` 表の最大値）③ `/stats/overview` とホームの件数・賞金総額 ④ タグの一覧と人気のタグ（非公開の大会にだけ付いたタグの名前が出る）⑤ Bot 用の `/api/v1/bot/activity`（Bot の秘密が要る。初期公開では Bot が無効） |
| LOW（S7） | 大会を公開から限定公開・非公開へ変えても、公開の集計のキャッシュは消さない（最長 15〜30 分残る）。順位の変動（▲▼）は週 1 回のスナップショットと比べるので、デプロイ後の最初のスナップショット（月曜 01:00 UTC）まではずれる |
| 仕様 | 辞退したチームは、自分では申請し直せない。主催者が承認し直す |
| 仕様 | 同じ大会に有効な登録が 2 つある利用者は、先に申請した方だけを表示・辞退できる |
| 仕様 | 選手成績の重複は、置き換えと行ロックと S8 の確認で防ぐ。DB の一意制約は入れていない（マイグレーションを増やさないため） |
| 仕様 | OCR は 16,777,216 画素・一辺 8192px まで。同時に 2 件まで（3 件目は 429 で、少し待てば通る）。8,388,608 画素を超える画像では、ログに Pillow の警告が 1 行出る |
| 仕様 | 再開しても、ゲームの記録は残る（登録し直したゲームの成績は置き換わるが、登録しなかったゲームはそのまま） |
| 初期公開で無効 | Discord 連携・Bot、Riot 連携（設定しない） |
| LOW | 前工程の監査資料の S14・S15。Ban/Pick の件数と `order` に上限がない、配信 URL のスキームを確かめていない、管理画面で `viewer` ロールを選ぶと 500 など |
