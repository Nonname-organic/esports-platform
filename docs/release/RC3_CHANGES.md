## 1. S7 一覧に載らない大会を、公開の集計に数えない

一覧に載る大会の条件は RC1 の `publicly_listed()`（`backend/app/repositories/tournament.py`。`is_public`、`visibility = 'public'`、下書きでない）。
RC1 で大会の一覧・検索・ホーム・優勝ハイライト・選手の大会履歴に入れた条件を、残っていた集計にも入れた。

| ファイル | 変更 |
|---|---|
| `backend/app/achievements/aggregator.py` | チームの実績カード（優勝・準優勝・ベスト4・出場大会数・直近のタイトル） |
| `backend/app/rankings/aggregator.py` | 公開ランキング（チームの RP）とランクカードの履歴。選手の RP はチームの RP から出すので一緒に直る |
| `backend/app/services/career_service.py` | チーム・選手の通算成績（勝敗・連勝・対戦相手・マップ・エージェント・マップ単位の勝敗・優勝数）。生 SQL の 2 か所は同じ条件を使えるよう SQLAlchemy に書き換えた（結果の並び・数え方は同じ） |

## 2. S8 成績は出場する 2 チームの所属選手のぶんだけ

| ファイル | 変更 |
|---|---|
| `backend/app/services/match.py` | `_check_player_stats` を追加。マップごとの保存（`save_game_player_stats`）と結果の登録（`register_result`。Bot の結果確定もここを通る）の両方で、書き込みの前に確かめる。チームが試合の 2 チームか、選手がそのチームに所属しているか、同じ選手が 2 回入っていないか。違反は 400 で、何も書かない。所属は、試合の期間と重なる所属行で見る（開始の前に抜けていない。終わった試合なら、終わる前に入っていた。後者は独立監査の指摘 S8-1 で追加） |

所属は本人の承諾なしに作れるため、大会と出場チームの両方を持つ利用者は、試合の前か試合中に他人を所属させて成績を書ける。
これは所属の仕組み（以前からの仕様）の問題で、コードに `shortcut:` として残し、[RC3_RELEASE_NOTES.md](RC3_RELEASE_NOTES.md) の制限事項に書いた。

## 3. S9 パスワードの変更・再設定で、それ以前のトークンを失効させる

| ファイル | 変更 |
|---|---|
| `backend/app/core/security.py` | `password_stamp`（パスワードのハッシュの HMAC-SHA256 の先頭 32 桁）、`stamp_matches`（印の無いトークンも通さない）、`issue_tokens`（ログインと更新で渡す 2 つのトークン）。リフレッシュトークンにも印を入れられるよう `create_refresh_token` に `extra` を足した |
| `backend/app/core/dependencies.py` | 認証（`get_current_user`、任意認証の `get_optional_user`）で、トークンの印と今のハッシュの印を比べる。`get_current_user_id` は中身を返す `get_access_payload` に置き換えた（呼び出し元はこのファイルの中だけ） |
| `backend/app/services/auth.py` | ログインと更新は `issue_tokens` で発行する。更新でも印を比べる |
| `frontend/src/app/(auth)/settings/page.tsx` | パスワードを変えたら、この端末もログアウトしてログイン画面へ移る |
| `frontend/src/app/(public)/login/page.tsx` | `?password_changed=1` のとき「パスワードを変更しました。新しいパスワードでログインしてください」を出す |
| `backend/scripts/e2e_organizer_flow.py` | 独立監査の指摘（L12）で追加。phase10 の「主催者の流れを通しで検証する」で使うスクリプトが、印の無いトークンを作っていた（RC3 では 401 になる）。ログインと同じ `issue_tokens` で作る |

トークンの保存場所（画面の localStorage）と方式（JWT）は変えていない。ログイン時に Redis へ書く jti（どこからも読まれていない）もそのまま。

## 5. RC3 に含めないもの（作業ツリーに残す）

RC2 と同じ。利用者の文書 3 本、レビュー・監査の資料、PR の準備資料、マニフェストはリポジトリに入れない。
RC3 の独立監査の結果（`RC3_AUDIT.md`）とマニフェスト（`RC3_MANIFEST.sha256`）も同じ扱い。
