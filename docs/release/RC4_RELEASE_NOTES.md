# RC4 リリースノート（AXELIA 大会一元管理プラットフォーム）

- 作成: 2026-11-11（RC4 自律完遂の工程）
- 対象: ブランチ `release/rc4`。RC3（`b7f49f1`）に、チームの所属を本人の承諾制にする変更（第 1 段）と、大会の名簿・試合の出場登録（第 2 段）を加えた版
- 設計の根拠は `docs/release/RC4_FINAL_DESIGN.md`（Q01〜Q32 の判断。リポジトリには入れない作業資料）
- 本番は RC2 より前の版（`sha-c0a80ad`、DB は 027）で動いている。**RC4 の公開は、RC2・RC3 の内容もまとめて本番に出す。**
  RC2・RC3 の内容は [RC2_RELEASE_NOTES.md](RC2_RELEASE_NOTES.md)・[RC3_RELEASE_NOTES.md](RC3_RELEASE_NOTES.md) のとおり
- 公開の手順は [RC4_DEPLOYMENT_RUNBOOK.md](RC4_DEPLOYMENT_RUNBOOK.md)、切り戻しは [RC4_ROLLBACK_RUNBOOK.md](RC4_ROLLBACK_RUNBOOK.md)、変更の詳細は [RC4_CHANGES.md](RC4_CHANGES.md)

## 本番への反映について（先に読む）

1. **マイグレーションは 028〜032 の 5 本。** Deploy の workflow が、バックアップの後、新しいイメージで**コンテナを入れ替える前に** 1 つのトランザクションで流す。
   開催中の大会か進行中の試合が 1 件でもあると 032 が止め、5 本ともまとめて戻る（版は 027 のまま、今のコードのまま動き続ける。公開は延期）
2. **公開の後、全利用者が一度ログインし直しになる**（RC3 の S9。トークンの形が変わるため）
3. **既存の大会はすべて旧方式（`legacy`）になる。** 名簿が無いので、開催中にできず、試合も開始できない。
   - 未開始の大会は、主催者が大会の管理画面の「名簿の方式に切り替える」で切り替える（一方向）。切り替えないまま開始の時刻を過ぎても、自動では開催中にならない（受付の終了・抽選は今のとおり自動で進む）
   - 完了・中止した大会は、そのまま記録として残る（再開はできない）
   - 新しく作る大会は、すべて名簿の方式
4. **既存の所属は、証拠のあるもの（チームのオーナー本人・本人が自分を加えたもの）だけ本人の承諾済みになる。** ほかは「本人未確認」で、
   移行の開始から 60 日は今までどおり数える。本人は「設定 → 所属の確認」で確認か否認をする。60 日を過ぎた本人未確認の所属は、大会の名簿・個人の実績に数えない
5. 同じチームに同じ選手の現役の所属が 2 行以上あったら、最も古い行を残して、ほかを脱退にする（`rc4_membership_dedup_backup` に退避。行は消さない）
6. **メンバーの直接追加（`POST /teams/{id}/members`）は 410 になる。** 画面の「メンバーを招待」は招待を送るようになり、本人が承認したときだけメンバーになる
7. 公開の直後に、Deploy の workflow が件数だけの確認（`scripts/rc4_release_check.py`）を行う。旧コードが動いていた間に始まった旧方式の大会の試合や、
   開催中の旧方式の大会があれば失敗にする（切り戻しの手順へ）

## 加わったもの

### 第 1 段: チームの所属は本人の承諾で決まる

| 内容 | 以前 |
|---|---|
| チームのオーナー・キャプテンは、ユーザー名で招待を送る。本人が「チームからの招待」で承認したときだけ所属になる。断った招待は 7 日間送り直せない。招待の期限は 7 日、返事待ちは 1 チーム 30 件まで | オーナー・キャプテンは、本人の承諾なしに誰でも所属させられた（RC3 の S8 の残る手口） |
| 所属に承諾の状態（作成者本人・招待を承認・本人が確認・本人未確認・本人が否認）を持つ。本人は自分の所属を確認・否認できる。否認は脱退として扱う。管理者は理由を記録して否認を取り消せる | 状態が無かった |
| キャプテンの権限（結果の報告・Ban/Pick・名簿の管理など）は、正式な所属（承諾済み、または移行期間中の本人未確認）のキャプテンだけが持つ | 所属していれば持った |

### 第 2 段: 大会の名簿と試合の出場登録

| 内容 | 以前 |
|---|---|
| 大会の名簿: 参加登録したチームのオーナー・キャプテンが、承諾済みのメンバーを載せ、本人が「大会の名簿への参加」で承認する。同じ大会では 1 チームの名簿にだけ載れる。名簿は大会の開始（または最初の試合の開始）で固定される | 名簿が無く、所属しているだけで成績を書けた |
| 試合の出場登録: 試合の開始で、名簿の既定の役目（スターター・控え）から作って固定する。スターターが出場人数（VALORANT は 5）に満たないチームがあれば、主催者は理由を入れて開始する。スターターのいないチームの試合は開始せず、**開始を経ない不戦勝**で決着する（取り消すと予定に戻る） | 開始に条件が無かった |
| 交代: マップの間の交代・マップの途中の交代（理由が必須）・補充を、主催者が理由つきで記録するか、チームの申請を主催者が承認する | 無かった |
| 成績を書けるのは、そのマップに出た選手だけ（出場登録 → 交代を反映した実出場）。チームを抜けた後でも、出場していた試合の成績は直せる | 試合の期間に所属していた選手（RC3） |
| 出場の異議: 出場登録・成績に載った本人は、試合のページから「出場していない」と異議を出せる。管理者が認めると、その試合の本人の成績を個人の記録に数えない | 無かった |
| 完了・中止した大会の成績・スコア・結果・名簿・出場登録・試合の再開は、管理者だけが理由を記録して直せる（訂正の記録が残る）。完了・中止した大会の状態を変えられるのも管理者だけ | 主催者も直せた。主催者が状態を戻せば何でも直せた |
| チームの結果報告の確定で予定の試合を自動で開始するのは、大会が開催中（名簿が固定済み）のときだけ。それより前は主催者が試合を開始する | 大会の開始の前でも、チームの確定で試合が始まった |
| マップの番号は 1〜9 だけを受け付ける | 上限が無かった |

### 個人の実績・RP の帰属（S8-2）

| 内容 | 以前 |
|---|---|
| 個人の RP・大会履歴は、名簿の方式の大会では、そのチームとして 1 マップ以上出場した選手だけに付く。旧方式の大会では、大会の期間と重なる所属の選手に付く（本人否認は数えない。本人未確認は移行期間中だけ数える） | 今の所属で近似していた（後から所属させた人にも付いた） |
| 同じ大会で 2 チームに当たる選手は、良い方の 1 回だけ数える（区分 → 勝ち数 → 参加登録の早い方） | 2 回数えた |
| 異議が認められた試合の選手は、個人の通算成績・実績・RP に数えない（行は消さない） | — |

## 画面

| 画面 | 内容 |
|---|---|
| チームのメンバー管理 | 「メンバーを招待」は招待を送る。返事待ちの招待の一覧と取り消し。本人未確認の所属に印 |
| マイチーム → 届いた招待（`/teams/invitations`） | 招待の承認・辞退 |
| 設定 → 所属の確認（`/settings/memberships`） | 本人未確認の所属の確認・否認（期限を表示） |
| 設定 → 大会の名簿への参加（`/tournaments/roster-invitations`） | 名簿への参加の承認・辞退・取り下げ（固定の前まで） |
| 大会ページのエントリー欄 | 参加登録したチームのオーナー・キャプテンに名簿の欄（載せる・役目・外す） |
| 主催者の大会管理 | 大会の方式の表示。旧方式の未開始の大会は「名簿の方式に切り替える」 |
| 試合管理 | 開始の理由、開始せずに不戦勝、出場登録と交代の記録・申請の承認、再開の理由 |
| 試合ページ | 出場登録の表示と、本人の出場の異議 |
| 管理者 → 出場の異議（`/admin/disputes`） | 異議の裁定 |

## マイグレーション

| 版 | 内容 | 戻すとき |
|---|---|---|
| 028〜030 | RC2 のとおり | 戻さない（RC2 のとおり） |
| 031 | 招待の表、所属の承諾の状態（既存は証拠のあるものだけ `self`、ほかは `unconfirmed`）、現役の重複の退避と脱退、期間の CHECK（違反があれば `NOT VALID` のまま）、現役の所属の一意制約、移行期間の表（60 日） | `downgrade 030` で、退避した重複が現役に戻り、列と表が消える（RC4 の切り戻しでは使わない） |
| 032 | 大会の方式（既存は `legacy`、新しい大会の既定は `roster`）と判定 3（開催中の大会・進行中の試合があれば止める）、名簿・出場登録・交代・異議・管理者の訂正の表、`legacy` の行の作成と `roster → legacy` を断るトリガー | `downgrade 031` で表と列が消える（RC4 の切り戻しでは使わない） |

- どちらも `lock_timeout = 10s`。ログに出すのは件数だけ
- 上げ下げ（030 → 032 → 030 → 032）、判定 3 での停止とまとめての戻り、トリガー、退避と戻しは、テスト（`backend/tests/test_rc4_migrations.py`）で PostgreSQL 15・16 の両方で確かめた

## 公開時の制限事項

| 区分 | 内容 | 扱い |
|---|---|---|
| 画面 | チームが試合の前に出場登録（スターター・控え）を組み替える画面と、チームからの交代の申請の画面は無い。名簿の既定の役目で出場登録を作り、交代は主催者が記録する（API はある） | 公開後の改善 |
| 画面 | 管理者による否認の取り消しは API だけ（`POST /api/v1/admin/memberships/{id}/unreject`） | 公開後の改善 |
| 画面 | 完了した大会の訂正のうち、画面で行えるのは試合の再開と結果の確定（理由の欄）だけ。マップのスコア・選手の成績の訂正は API に `correction_reason` を付けて行う | 公開後の改善 |
| 画面 | 出場人数・名簿の上限を大会ごとに変える入力欄は無い。今選べるゲームは VALORANT だけで、既定（5・7）を使う | ほかのゲームを選べるようにするときに足す |
| 進行 | チームの結果報告で予定の試合が自動で開始されるとき、スターターが足りないチームがあると確定できない（理由が要るため）。主催者が理由を入れて開始してから報告を確定する | 想定どおり（人数不足の開始は主催者の判断） |
| 進行 | 旧方式の未開始の大会は、主催者が切り替えるまで開催中にならない | 公開の前後に主催者へ知らせる |
| 公開範囲 | 試合の出場登録（選手のゲーム内の名前）は、試合のページを見られる人に見える（試合の詳細・成績と同じ扱い。限定公開の大会は URL を知っている人だけ） | 設計どおり（D18） |
| RC2・RC3 | RC2・RC3 のリリースノートの「公開時の制限事項」のうち、S8 の残る手口（本人の承諾なしの所属）は RC4 で解消した。ほかはそのまま | — |
