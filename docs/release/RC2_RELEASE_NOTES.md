- 作成: 2026-11-09（RC2 統合・必須修正工程）
- 対象: ブランチ `release/rc2`。RC1（`b3fdf11`）に main（`262bff2`）を取り込み、必須の修正を加えた版
- 識別情報（コミット・ツリー・マニフェスト）とテスト結果は PR の本文に載せる
- **本書は本番公開の承認ではない。** RC2 の完成と本番公開は別の判断になる
- RC1 の機能・修正（[RC1_RELEASE_NOTES.md](RC1_RELEASE_NOTES.md)）はすべて含む。RC1 の文書のうち、
  本番の手順（チェックリスト・phase10 の RC1 の節）は RC2 の文書で置き換えた

## 本番への反映について（先に読む）

- 本番の Deploy workflow（Deploy — Demo）は 2026-10-12 から**無効**のまま。今は main へマージしても、
  Build & Push がイメージを作るだけで、本番は変わらない
- Deploy を有効にすると、その後の main の Build & Push の成功で、本番のコンテナの入れ替えとマイグレーション 028〜030 が自動で走る。
  **Deploy の有効化が本番適用の開始になる**
- サーバー側の compose・nginx の設定は Deploy では更新されない。公開の前に別の作業が要る（[RC2_DEPLOYMENT_RUNBOOK.md](RC2_DEPLOYMENT_RUNBOOK.md)）
- 切り戻しはイメージの版と digest を指定して戻す。DB は戻さない（[RC2_ROLLBACK_RUNBOOK.md](RC2_ROLLBACK_RUNBOOK.md)）

### セキュリティ

| # | 内容 |
|---|---|
| S1 | **スコアボード OCR のメモリ枯渇を防いだ。** 画像を展開する前にヘッダーだけを読み、PNG・JPEG・WebP 以外、一辺 8192px 超、16,777,216 画素（4096×4096）超の画像を断る。以前は数百 KB の PNG 1 枚で API（メモリ上限 1GB）を落とせた。あわせて、同時に解析するのは 2 件までにした（3 件目は 429） |
| S2 | **ログイン後の外部サイトへの転送を防いだ。** `?next=` は同じサイトの相対パスだけを受け付け、`//host`・`/\host`・絶対 URL・`javascript:`・タブや改行を含む値などは `/dashboard` に戻す |
| Discord | アプリの管理者が大会の Discord を設定するときも、Discord 側のサーバー管理権限を確かめる（アプリの役割と Discord の権限は別物として扱う） |

### 試合の整合性

| 内容 | 以前 |
|---|---|
| 試合を再開すると、その試合と、勝ち上がりを取り消した次の試合の、チームの報告・確認・異議を消す。両チームが最初から報告し直す | 古い報告が残り、相手が入れ替わった後に、片方のチームの確認だけで結果が確定しえた |
| 結果の登録は、ゲームごとの選手成績を置き換える | 再開後に登録し直すと、成績が二重に入り、公開の通算成績が水増しされた |
| 同じ試合への開始・スコア・成績・結果・再開・チームの報告は、1 件ずつ処理する（DB の行ロック） | 同時に操作すると、成績が二重に入ったり、更新が消えたりしえた |
| 異議の理由は、両チームのオーナー・メンバーと、主催者・管理者だけが見られる | ログインした全員に見えた |
| 異議中は、チームからは報告し直せない（主催者は結果の登録で裁定できる） | フォームが出るが、送ると必ず失敗した |

### 参加の辞退

| 内容 | 以前 |
|---|---|
| 辞退ボタンは、チームのオーナー・キャプテンにだけ出る | 一般メンバーにも出て、押すと 403 だった |
| 主催者は、辞退した登録を承認し直して、辞退を取り消せる | 取り消す方法がなかった |
| 複数のチームで同じ大会に関わる利用者には、有効な登録（審査中・承認・補欠）を表示し、辞退もその登録に対して行う | 古い辞退済みの登録が表示され、有効な方を辞退できなかった |

  結果報告の表が消える。後者は応募が連鎖して消え、元に戻せない

## 公開時の制限事項

| 区分 | 内容 |
|---|---|
| 未対応（MEDIUM） | 非公開・限定公開の大会が、チームの実績カードとランキングの履歴に出る（S7） |
| 未対応（MEDIUM） | 主催者は自分の試合で、出場していない選手の成績も書ける（S8） |
| 未対応（MEDIUM） | パスワードを変えても、既存のセッションは失効しない（S9） |
| 未対応（MEDIUM） | 異議は誰にも通知されず、異議の記録（`match_disputes`）の一覧・解決の画面がない。主催者は試合ページで状態を見て裁定する（S11） |
| 手順で回避（MEDIUM） | デプロイの途中、新しいコードが 027 のスキーマで動く間（最大 60 秒ほど）は、結果の登録・確認が 500 になる。先にマイグレーションを流す手順で避ける（S13、[デプロイ手順](RC2_DEPLOYMENT_RUNBOOK.md)） |
| 仕様 | 辞退したチームは、自分では申請し直せない。主催者が承認し直す |
| 仕様 | 同じ大会に有効な登録が 2 つある利用者は、先に申請した方だけを表示・辞退できる |
| 仕様 | 選手成績の重複は、置き換えと行ロックで防ぐ。DB の一意制約は入れていない（マイグレーションを増やさないため） |
| 仕様 | OCR は 16,777,216 画素・一辺 8192px まで。同時に 2 件まで（3 件目は 429 で、少し待てば通る）。8,388,608 画素を超える画像では、ログに Pillow の警告が 1 行出る |
| 仕様 | 再開しても、ゲームの記録は残る（登録し直したゲームの成績は置き換わるが、登録しなかったゲームはそのまま） |
| 初期公開で無効 | Discord 連携・Bot、Riot 連携（設定しない） |
| LOW | 前工程の監査資料（`RC2_SECURITY_REVIEW.md`。リポジトリには含めない）の S14・S15。Ban/Pick の `order` に上限がない、配信 URL のスキームを確かめていない、管理画面で `viewer` ロールを選ぶと 500 など |
